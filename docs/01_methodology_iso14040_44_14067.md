# Methodology: ISO 14040/44 and ISO 14067 in this repository

## The standards in one paragraph each

- **ISO 14040:2006** sets the principles and framework of life cycle assessment (LCA): four iterative phases (goal and scope, inventory analysis, impact assessment, interpretation), the functional unit, the system boundary, and critical review.
- **ISO 14044:2006** turns that framework into requirements: data quality requirements, the allocation hierarchy, cut-off criteria, the inventory calculation procedure, sensitivity and uncertainty checks during interpretation, and reporting.
- **ISO 14067:2018** applies LCA to a single impact category, climate change. Its result is the *carbon footprint of a product* (CFP, often called a PCF) in kg CO2e. It adds GHG-specific rules: GWP100 characterisation, reporting fossil and biogenic emissions and removals separately, treatment of electricity (including how contractual instruments may be used), aircraft emissions, land-use change, and what a CFP study report and CFP-PCR must contain. A *partial* CFP (cradle-to-gate) is allowed when downstream stages are out of scope.

## The four ISO 14040 phases mapped to code

| ISO phase | What it means | Where it lives |
|---|---|---|
| **Goal & scope** | Intended application, declared/functional unit, system boundary, cut-off, allocation, data quality requirements, GWP method | `config/study.yaml`, `products/*.yaml` |
| **Life cycle inventory (LCI)** | Collect activity data, link to emission factors, calculate flows per declared unit | `src/pcf/calculator.py` → `inventory.csv` |
| **Impact assessment (LCIA)** | Characterise flows with GWP100 (IPCC AR6) | EFs are expressed directly in kg CO2e (AR6 GWP100), so characterisation is built into each factor |
| **Interpretation** | Hotspots, completeness/consistency/sensitivity checks, uncertainty, conclusions and limitations | `sensitivity.py`, `uncertainty.py`, `validation.py`, `report.py` |

## Declared unit vs functional unit

A **functional unit** quantifies the function delivered ("providing pointer input for 4 years of office use"), which you need when comparing two products. A **declared unit** is a physical quantity ("1 mouse with packaging") used when the function isn't being compared. This project uses declared units with the lifetime stated in each one, which is how most brands publish electronics PCFs.

## Calculation: activity data × emission factor

Every inventory line is

```
kg CO2e = activity amount (kg, kWh, tkm, unit) × emission factor (kg CO2e per unit)
```

| Stage | Activity data | Typical emission factor |
|---|---|---|
| Raw materials | BOM net mass ÷ (1 − process scrap rate) | kg CO2e/kg material (cradle-to-gate) |
| Packaging | Packaging BOM mass | kg CO2e/kg board, pulp, film |
| Production | kWh from process intensity × gross mass; metered assembly kWh; allocated overhead kWh | grid mix kg CO2e/kWh for the plant's location |
| Distribution | (product + packaging mass) × logistics overhead × km, as tkm | kg CO2e/tkm by mode and region |
| Use | kWh/year × lifetime; replacement consumables | grid mix of the market; kg CO2e/battery cell |
| End of life | Mass by material group × fate fractions (recycle / incinerate / landfill / WEEE) | kg CO2e/kg treated |

**Gross vs net mass.** A 180 g CNC-machined aluminium case with 15% scrap needs 212 g of input metal. Using net mass understates material impacts, so the calculator always uses gross input.

## Key methodological choices (and why)

| Topic | Choice | Rationale |
|---|---|---|
| End-of-life allocation | **Cut-off / recycled-content approach** | Recycled input carries only recycling burdens, and no credit is given for recycling at end of life. This matches how most electronics PCF methodologies work and avoids double counting. Potential credits are calculated and **reported separately** (`recycling_credits_reported_separately.csv`). |
| Factory overhead | **Physical (mass) allocation**, tested against units and economic | ISO 14044 hierarchy: avoid allocation → physical relationship → other (economic). The allocation sensitivity table shows how much the choice matters. |
| Supplier primary data | Used only if cradle-to-gate, ≤3 years old and verified or self-declared | Primary data replaces the secondary dataset completely for that part, so no double counting. Self-declared data is accepted with a reliability score of 3. |
| Biogenic carbon | Fibre-packaging removal and release **tracked separately** and excluded from the headline total | ISO 14067 requires biogenic emissions and removals to be documented separately |
| Cut-off | ≤1% excluded mass **and** ≤1% estimated impact (conservative proxy factor) | Mass-only cut-off can hide small, high-impact parts such as ICs, so the impact test is applied as well |
| Electricity in production | Location-based grid mix by default; market-based (PPA) only in a named scenario | Keeps the baseline conservative and makes contractual-instrument claims explicit |
| Uncertainty | Pedigree matrix → lognormal GSD → Monte Carlo (10,000 runs) | Standard practice in ecoinvent-based LCA |

## Data quality

Each line gets five pedigree scores (1 = best, 5 = worst):

| Indicator | Question | How it's scored here |
|---|---|---|
| Reliability | Measured, calculated or estimated? Verified? | From the dataset; supplier data uses its verification status |
| Completeness | Representative sample? | From the dataset |
| Temporal | How old is the data relative to the study year? | Computed: ≤3 years = 1, ≤6 = 2, ≤10 = 3, ≤15 = 4, otherwise 5 |
| Geographical | Same region as the activity? | Computed from the region hierarchy: exact = 1, parent region = 2, global = 3, other region = 4 |
| Technological | Same technology? | From the dataset; generic process-energy intensities floored at 3 |

The **DQR** of a line is the mean of its five scores. The product DQR is weighted by each line's contribution to the total, and the PEF-style bands are ≤1.6 Excellent, ≤2.0 Very good, ≤3.0 Good, ≤4.0 Fair. Temporal and geographical scores depend on context: the same aluminium dataset scores differently for a part made in China and one made in Germany.

## Interpretation checks performed

1. **Completeness check:** every BOM line is mapped to an EF and an end-of-life group, and the cut-off is tested (`validation.py`).
2. **Consistency check:** one system model, one GWP method and one reference year across all products.
3. **Sensitivity check:** ±20% tornado on seven parameters, plus allocation-key and eco-design scenarios.
4. **Uncertainty:** 95% interval from Monte Carlo.
5. **Hotspot analysis:** top contributors by component and process.

## What a real study would add

- Licensed background data (ecoinvent / Sphera MLC) in place of the illustrative library.
- Activity-data uncertainty and correlated sampling.
- Critical review (ISO/TS 14071) before any public comparative claim.
- A product category rule (CFP-PCR) for the product category, if one exists.
